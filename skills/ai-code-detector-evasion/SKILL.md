# Детекторы AI-кода: устройство и обход

## Границы применения

Легитимно: red-team оценка детекторов, аудит собственного кода перед политиковыми проверками, defender-сценарий (проверка чужого кода на AI-происхождение перед security-ревью — Pangram позиционирует это как security workflow), исследования атрибуции авторства. Политики компании/вуза пользователь знает сам — но в явном запросе на обман в рамках запрещающей политики помогай только в части оценки детекторов.

## Как работают детекторы кода

1. **Кодовая стилометрия** (Gurioli et al., SANER 2025, «Is This You, LLM?»): transformer-энкодер поверх структурных и лексических фич; LLM-код имеет устойчивую структурную сигнатуру (стиль именования, плотность комментариев, идиомы, шаблонность). Мультиязычная атрибуция возможна, но качество падает вне обучающего распределения.
2. **Perplexity/perturbation**: у LLM-кода ниже перплексия; пертурбационные методы (как DetectGPT, но для кода). Результаты смешанные.
3. **CodeVision** (arXiv 2501.03288): 2D-карта вероятностей токенов → vision-модель классифицирует «текстуру» генерации.
4. **Watermarking**: green/red-list по словарю кодовых токенов (Lee et al.) — внедряется генератором, снимается рефакторингом.
5. **Коммерческие сервисы**: Pangram Code и др.; независимых бенчмарков мало, точность ниже текстовых аналогов.

Ключевой факт из литературы: **публично доступные детекторы кода работают плохо**; >90% accuracy демонстрируется только в узких контекстах (CS1-задачи, одна модель, без правок). Реальный код с человеческими правками — тяжёлая задача для любого детектора.

## Методы обхода (по эффективности)

1. **Человеческие правки** — главный метод: даже умеренное перемешивание (ручной рефакторинг 20–30% сущностей) разрушает глобальную стилометрическую сигнатуру. Это же естественный рабочий процесс.
2. **Рефакторинг-проходы**: смена идиом (list comprehension ↔ цикл, early return ↔ вложенность), замена stdlib-вызовов альтернативами, переупорядочивание функций, изменение структуры модулей. AST-уровень: переименование + перестановка не меняет семантику, но смещает фичи.
3. **Стилевая нормализация под человека**: LLM пишет «учебниково» (избыточные docstring каждой функции, uniform-комментарии, защитный код везде). Убрать шаблонность: неравномерные комментарии, лаконичные имена там, где LLM многословен.
4. **Генерация другой моделью**: сигнатуры model-specific; локальные модели (локальный llama.cpp, edge-serving движки) дают другой статистический профиль, чем фронтирные API, на которых обучены детекторы.
5. **Парафраз кода** (перегенерация фрагментов с другими сидами/температурой): аналог рекурсивного парафраза для текста; есть работы по детекции именно code paraphrasing — учитывать при сильной автоматизации.
6. **Форматтеры**: `black`/`ruff format` и т.п. выравнивают поверхностные фичи — слабый метод в одиночку, полезен как первый проход.

## Методика замера (обязательный цикл)

1. Определи целевой детектор (каким реально будут проверять — это критично, ландшафт фрагментирован).
2. До/после: score на целевом + 1–2 независимых; per-file и per-snippet.
3. Контроль корректности: рефакторинг-проходы обязаны сохранять тесты зелёными — сломанный код ради «человечности» недопустим.
4. Учитывай, что вердикт детектора кода сам по себе слабое доказательство (высокий FPR на идиоматичном человеческом коде) — это аргумент и для defender-, и для offender-стороны.

## Defender-сторона (когда проверяешь чужой код)

- Verdict «100% AI» → не вывод, а триггер ручного security-ревью (позиция Pangram — методологически правильная).
- Смотри сигналы вне детекторов: git-история (один гигантский коммит вместо эволюции), отсутствие промежуточных артефактов, несвойственная человеку uniform-ность.
- Для корпоративной политики: детектор кода = индикатор, не доказательство; юридически значимым его не делай.

## Антипаттерны

- Полагаться на один переименователь идентификаторов (стилометрия смотрит глубже лексики).
- Обещать непалевность при нулевых правках (сырая генерация фронтирной модели детектируется лучше всего).
- Ломать тесты/типизацию ради обфускации.
- Игнорировать версионный след: обход в файле не отменяет историю коммитов/CI-артефакты.

## Источники для углубления

- Gurioli et al., SANER 2025 «Is This You, LLM?» (multilingual code stylometry); arXiv 2409.01382 «Automatic Detection of LLM-Generated Code»; CodeVision arXiv 2501.03288; Lee et al. 2024 (green/red-list code watermarking); arXiv 2502.17749 (detection/tracing LLM code paraphrasing); Leppänen et al. 2025 (обзор: публичные детекторы слабые).
